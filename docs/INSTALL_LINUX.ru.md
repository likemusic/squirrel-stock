# Установка SquirrelStock на Linux без Docker (Debian 13, Debian 12, Ubuntu 24.04)

Для отдельного компьютера на складе (в том числе слабого, с минимальной системой без рабочего стола) или для VPS. Ставится одним скриптом: Apache с модулем PHP, MariaDB, rclone для облачных копий и расписание резервных копий.

Пометки: **[проверено]** — пройдено в контейнере скриптом `tools/install/test-in-docker.sh`: `debian:12` 15.10.2026 с пустой базой и с `--demo`, `debian:13` (PHP 8.4.26, MariaDB 11.8.6) 17.10.2026 с пустой базой, после перехода на пакеты дистрибутива 18.10.2026 — `debian:12` (PHP 8.2.34, MariaDB 10.11.19) с пустой базой и с `--demo` (повторный запуск — 73 документа на месте) и `ubuntu:24.04` (PHP 8.3.6, MariaDB 10.11.14) с пустой базой, включая повторный запуск и logrotate (без systemd: службы запускаются через `service`); **[не проверено]** — на настоящем Debian или Ubuntu на железе и на VPS скрипт ещё не запускался; полный набор автотестов на PHP 8.4 пройден на Docker-стенде (с MariaDB 11.4, не 11.8).

## 1. Что нужно

- Debian 13 (рекомендуется: PHP 8.4, MariaDB 11.8), Debian 12 (PHP 8.2, MariaDB 10.11) или Ubuntu 24.04 (PHP 8.3, MariaDB 10.11), доступ root (или `sudo`), интернет на время установки (пакеты, зависимости composer).
- Копия репозитория SquirrelStock на этом компьютере (`git clone`) **или** пакет `squirrel-stock-<версия>.zip` из `tools/release/build.sh` вместе с репозиторием (из него берутся файлы базы `db/`).
- Около 1 ГБ места; памяти хватает 1 ГБ (Apache с mod_php и MariaDB). **[не проверено]** на 1 ГБ.

PHP и MariaDB ставятся из пакетов самого дистрибутива: их исправления безопасности приходят обычным `apt upgrade`. Сторонние репозитории (sury.org для PHP, репозиторий MariaDB) скрипт не подключает: это ещё один источник пакетов с правом root, который может отстать или пропасть, а обновление системы с ним иногда ломается. Для новой установки берите Debian 13. Debian 12 подходит: его PHP 8.2 и после окончания поддержки у разработчиков PHP (31.12.2026) получает исправления безопасности от Debian, в рамках Debian LTS до 30.06.2028 **[по документации Debian, не проверено]**. PHP старше 8.2 скрипт не принимает.

## 2. Установка

```bash
sudo tools/install/linux.sh                  # сайт из этой копии репозитория, пустая база
sudo tools/install/linux.sh --demo           # демо-база с вымышленными данными вместо пустой
sudo tools/install/linux.sh --zip=dist/squirrel-stock-<версия>.zip   # сайт из готового пакета (composer не нужен)
```

Параметры: `--dir=/var/www/squirrelstock` (папка сайта), `--port=80`, `--servername=stock.example.org` (имя сайта для Apache), `--no-profile` (не применять профиль благотворительной организации к пустой базе).

Что делает скрипт:

1. Ставит пакеты: `apache2`, `libapache2-mod-php`, PHP с расширениями (mysqli, zip, gmp, gd, mbstring, curl, xml, intl), `mariadb-server`, `rclone`, `cron`; для установки из git-копии — `composer`. **[проверено]**
2. Копирует сайт в `/var/www/squirrelstock` и ставит зависимости (`composer install`). **[проверено]** Установка из пакета `--zip` — **[не проверено]**.
3. Создаёт базу `squirrelstock` и пользователя с случайным паролем, пишет их в `config/config.php` (права 640, владелец www-data). **[проверено]**
4. Загружает пустую базу (`db/db.sql` + `www/app/sqs/schema.sql`) или демо (`--demo`), ставит **случайный пароль admin** и случайную «соль» — как пакет `tools/release/build.sh`. К пустой базе применяет профиль благотворительной организации и русские названия (`cli/charity-profile.php`, `cli/localize-db.php ru`). **[проверено]**
5. Настраивает PHP (лимиты и часовой пояс Europe/Minsk, как на Docker-стенде) и Apache: сайт `squirrelstock` с `AllowOverride All`, модули `rewrite` и `headers`; папки `config`, `logs`, `cli` из браузера закрыты; заголовки безопасности, в том числе Content-Security-Policy, берутся из `.htaccess` сайта. **[проверено]**: `/config/config.php`, `/logs/`, `/cli/backup.php` отвечают 403, скрипты фреймворка из `vendor/` отдаются, заголовок Content-Security-Policy есть.
6. Ставит расписание резервной копии: `/etc/cron.d/squirrelstock` — каждый час `cli/backup.php --if-older=20`, то есть копия раз в сутки, а если компьютер был выключен — после включения. Копии — в `/var/www/squirrelstock-backup`; сетевая папка и облака (одно или несколько, по одному remote rclone в строке) настраиваются на странице «Сервисные страницы → Резервная копия» ([BACKUP.ru.md](BACKUP.ru.md)). **[проверено]**: `cli/backup.php` делает копию с кодом 0; срабатывание cron в контейнере не проверялось. Журналы `logs/backup-cron.log` и `logs/update.log` ротирует logrotate (`/etc/logrotate.d/squirrelstock`: раз в месяц, 12 архивов; **[проверено]** принудительным `logrotate -f` в debian:13 17.10.2026, в debian:12 и ubuntu:24.04 18.10.2026), журнал программы `logs/log-*.txt` программа хранит сама 7 дней.
7. В конце печатает адрес, логин `admin` и пароль. **Пароль показывается один раз** и нигде не сохраняется — запишите его; сменить можно в профиле пользователя.

Почему Apache с mod_php, а не php-fpm: одна служба вместо двух, меньше памяти на слабом компьютере; так же устроены Docker-стенд (`php:8.4-apache`) и обычный хостинг, поэтому `.htaccess` и настройки PHP работают одинаково.

## 3. Повторный запуск и обновление

Скрипт можно запускать снова — например, после `git pull` для обновления программы. Пакеты доустанавливаются; если база уже есть, сначала делается резервная копия в `/var/www/squirrelstock-backup/before-update/`; код сайта заменяется (файлы, которых нет в новой версии, удаляются), а `config/config.php`, `upload/` и `logs/` остаются; база не пересоздаётся, новые таблицы и пункты меню SquirrelStock добавляет `cli/modules.php`; пароль admin не меняется; версия «было → стало» печатается и пишется в `logs/update.log`. **[проверено]**: повторный запуск проходит, пароль и документы на месте, вход работает (на пустой базе и на демо).

Порядок обновления, откат и что проверено — [UPDATE.ru.md](UPDATE.ru.md).

## 4. После установки

- Откройте напечатанный адрес, войдите как `admin`, смените пароль в профиле.
- Пустая база: дальше — [GUIDE.ru.md](GUIDE.ru.md), раздел «Начальная настройка» (профиль и русские названия уже применены скриптом).
- Доступ из интернета (VPS): нужен HTTPS — например, `apt install certbot python3-certbot-apache && certbot --apache -d stock.example.org` **[не проверено]**; без HTTPS пароль идёт открытым текстом. Рекомендации по заголовкам и cookie сессии — [INSTALL_HOSTING.ru.md](INSTALL_HOSTING.ru.md).
- Внутри склада без интернета программа работает полностью: внешних запросов нет.

## 5. Проверка скрипта в контейнере

```bash
tools/install/test-in-docker.sh                     # debian:13 (по умолчанию)
tools/install/test-in-docker.sh debian:12           # пустая база
tools/install/test-in-docker.sh debian:12 --demo    # демо-база
tools/install/test-in-docker.sh ubuntu:24.04
```

Скрипт поднимает чистый контейнер, ставит программу, проверяет главную, закрытые папки, вход admin с напечатанным паролем (браузером Playwright из `tests/`, если он установлен), резервную копию и повторный запуск, затем удаляет контейнер. Прогон — от 2 до 10 минут, в основном скачивание пакетов.
