# Установка SquirrelStock на Linux без Docker (Debian 12, Ubuntu 24.04)

Для отдельного компьютера на складе (в том числе слабого, с минимальной системой без рабочего стола) или для VPS. Ставится одним скриптом: Apache с модулем PHP, MariaDB, rclone для облачных копий и расписание резервных копий.

Пометки: **[проверено]** — пройдено 15.10.2026 в контейнере `debian:12` скриптом `tools/install/test-in-docker.sh`, с пустой базой и с `--demo` (без systemd: службы запускаются через `service`); **[не проверено]** — на настоящем Debian или Ubuntu на железе и на VPS скрипт ещё не запускался, Ubuntu 24.04 не проверялась вовсе (там PHP 8.3 вместо 8.2).

## 1. Что нужно

- Debian 12 или Ubuntu 24.04, доступ root (или `sudo`), интернет на время установки (пакеты, зависимости composer).
- Копия репозитория SquirrelStock на этом компьютере (`git clone`) **или** пакет `squirrel-stock-<версия>.zip` из `tools/release/build.sh` вместе с репозиторием (из него берутся файлы базы `db/`).
- Около 1 ГБ места; памяти хватает 1 ГБ (Apache с mod_php и MariaDB). **[не проверено]** на 1 ГБ.

## 2. Установка

```bash
sudo tools/install/linux.sh                  # сайт из этой копии репозитория, пустая база
sudo tools/install/linux.sh --demo           # демо-база с вымышленными данными вместо пустой
sudo tools/install/linux.sh --zip=dist/squirrel-stock-<версия>.zip   # сайт из готового пакета (composer не нужен)
```

Параметры: `--dir=/var/www/squirrelstock` (папка сайта), `--port=80`, `--servername=stock.example.org` (имя сайта для Apache), `--no-profile` (не применять профиль благотворительной организации к пустой базе).

Что делает скрипт:

1. Ставит пакеты: `apache2`, `libapache2-mod-php`, PHP с расширениями (mysqli, zip, gmp, gd, mbstring, curl, xml, intl), `mariadb-server`, `rclone`, `cron`; для установки из git-копии — `composer`. **[проверено]**
2. Копирует сайт в `/var/www/squirrelstock` и ставит зависимости (`composer install`). **[проверено]** Установка из пакета `--zip` — **[не проверено]**.
3. Создаёт базу `squirrelstock` и пользователя с случайным паролем, пишет их в `config/config.php` (права 640, владелец www-data). **[проверено]**
4. Загружает пустую базу (`db/db.sql` + `db/squirrelstock.sql`) или демо (`--demo`), ставит **случайный пароль admin** и случайную «соль» — как пакет `tools/release/build.sh`. К пустой базе применяет профиль благотворительной организации и русские названия (`cli/charity-profile.php`, `cli/localize-db.php ru`). **[проверено]**
5. Настраивает PHP (лимиты и часовой пояс Europe/Minsk, как на Docker-стенде) и Apache: сайт `squirrelstock` с `AllowOverride All`, модули `rewrite` и `headers`; папки `config`, `logs`, `cli` из браузера закрыты; заголовки безопасности, в том числе Content-Security-Policy, берутся из `.htaccess` сайта. **[проверено]**: `/config/config.php`, `/logs/`, `/cli/backup.php` отвечают 403, скрипты фреймворка из `vendor/` отдаются, заголовок Content-Security-Policy есть.
6. Ставит расписание резервной копии: `/etc/cron.d/squirrelstock` — каждый час `cli/backup.php --if-older=20`, то есть копия раз в сутки, а если компьютер был выключен — после включения. Копии — в `/var/www/squirrelstock-backup`; сетевая папка и облака (одно или несколько, по одному remote rclone в строке) настраиваются на странице «Сервис → Резервная копия» ([BACKUP.ru.md](BACKUP.ru.md)). **[проверено]**: `cli/backup.php` делает копию с кодом 0; срабатывание cron в контейнере не проверялось.
7. В конце печатает адрес, логин `admin` и пароль. **Пароль показывается один раз** и нигде не сохраняется — запишите его; сменить можно в профиле пользователя.

Почему Apache с mod_php, а не php-fpm: одна служба вместо двух, меньше памяти на слабом компьютере; так же устроены Docker-стенд (`php:8.2-apache`) и обычный хостинг, поэтому `.htaccess` и настройки PHP работают одинаково.

## 3. Повторный запуск и обновление

Скрипт можно запускать снова — например, после `git pull` для обновления программы. Пакеты доустанавливаются, код сайта заменяется, а `config/config.php`, `upload/` и `logs/` остаются; база не пересоздаётся, к ней применяются дополнения `db/squirrelstock.sql` (безопасно повторять); пароль admin не меняется. **[проверено]**: повторный запуск проходит, пароль и документы на месте, вход работает (на пустой базе и на демо).

Перед обновлением сделайте резервную копию («Сервис → Резервная копия → Создать копию»).

## 4. После установки

- Откройте напечатанный адрес, войдите как `admin`, смените пароль в профиле.
- Пустая база: дальше — [GUIDE.ru.md](GUIDE.ru.md), раздел «Начальная настройка» (профиль и русские названия уже применены скриптом).
- Доступ из интернета (VPS): нужен HTTPS — например, `apt install certbot python3-certbot-apache && certbot --apache -d stock.example.org` **[не проверено]**; без HTTPS пароль идёт открытым текстом. Рекомендации по заголовкам и cookie сессии — [INSTALL_HOSTING.ru.md](INSTALL_HOSTING.ru.md).
- Внутри склада без интернета программа работает полностью: внешних запросов нет.

## 5. Проверка скрипта в контейнере

```bash
tools/install/test-in-docker.sh debian:12           # пустая база
tools/install/test-in-docker.sh debian:12 --demo    # демо-база
tools/install/test-in-docker.sh ubuntu:24.04        # не проверялось
```

Скрипт поднимает чистый контейнер, ставит программу, проверяет главную, закрытые папки, вход admin с напечатанным паролем (браузером Playwright из `tests/`, если он установлен), резервную копию и повторный запуск, затем удаляет контейнер. Прогон — около 10 минут, в основном скачивание пакетов.
