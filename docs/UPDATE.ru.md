# Обновление SquirrelStock

Данные живут в базе, в `upload/` (вложения, картинки) и в `config/config.php` (параметры базы). Обновление меняет только код программы: новые таблицы и пункты меню программа досоздаёт сама при первом входе после обновления (на Linux — сразу, скриптом установки), данные не переносятся и не пересоздаются.

Версия программы видна внизу левого меню («SquirrelStock 2026.10.16-d2489fb22»: дата и номер сборки) и на странице «Сервисные страницы → Обновление программы» вместе с историей обновлений.

## 1. Хостинг (ISPmanager)

- 1.1. **Резервная копия — первым делом.** «Сервисные страницы → Резервная копия» → «Создать копию»: браузер скачивает zip с базой и вложениями. Сохраните его у себя: из него можно вернуть данные, если что-то пойдёт не так.
- 1.2. Новый пакет `squirrel-stock-<версия>.zip` — из `tools/release/build.sh` ([INSTALL_HOSTING.ru.md](INSTALL_HOSTING.ru.md), раздел 1). Контрольную сумму можно сверить по файлу `.sha256`.
- 1.3. Менеджер файлов → корень сайта → закачать zip → **Извлечь** в текущую папку **с заменой** существующих файлов. Настроек пакет не затирает: в нём нет `config/config.php` (только `config/config.example.php`); из `upload/` и `logs/` в пакете только их `.htaccess`. Zip после распаковки удалить.
- 1.4. Войти в программу. Таблицы новой версии создаются при первом запросе.
- 1.5. «Сервисные страницы → Обновление программы»:
  - вверху — новая версия, внизу — запись «с версии → на версию»;
  - «Пакет распакован не полностью» — часть файлов не заменилась (оборвалась закачка, менеджер файлов не заменил существующие): извлечь пакет ещё раз;
  - «Файлы старых версий» — файлы, которых нет в новом пакете: при распаковке поверх они остаются. Нажать «Удалить файлы старых версий». Удаляются только файлы в папках программы (`app`, `assets`, `cli`, `lang`, `templates`, `vendor`); корень сайта, `config/`, `upload/`, `logs/` не трогаются (лишнее там показывается отдельным списком).
- 1.6. Проверка сайта снаружи — `tools/release/check-site.sh` ([INSTALL_HOSTING.ru.md](INSTALL_HOSTING.ru.md), раздел 9).

Зачем удалять файлы старых версий. Пока они лежат, программа работает: страницы, перенесённые в модули, загружаются из модулей. Но старый код остаётся на сервере: если модуль выключить, по адресу страницы откроется её старая копия без исправлений, сделанных после; файлы модуля, убранного из новой версии, продолжают загружаться [из кода; проверено, что после удаления всё открывается — раздел 4].

Откат на прежнюю версию [не проверено]: удалить папки `app`, `assets`, `cli`, `lang`, `templates`, `vendor`, извлечь прежний пакет, затем «Сервисные страницы → Резервная копия» → «Восстановить» из копии шага 1.1 (новые таблицы прежняя версия не использует, восстановление копии возвращает базу к моменту до обновления).

## 2. Linux (`tools/install/linux.sh`)

```bash
cd ~/squirrel-stock && git pull                                  # или новый пакет из tools/release/build.sh
sudo tools/install/linux.sh                                      # или: sudo tools/install/linux.sh --zip=dist/squirrel-stock-<версия>.zip
```

Скрипт делает всё сам:

- 2.1. Резервная копия до замены кода — старой версией программы, в `/var/www/squirrelstock-backup/before-update/` (zip, восстанавливается на странице «Сервисные страницы → Резервная копия»). Если старая версия копию сделать не смогла — `mysqldump` базы и архив `config.php` и `upload/` туда же.
- 2.2. Замена кода: файлы, которых нет в новой версии, удаляются; `config/config.php`, `upload/`, `logs/` остаются.
- 2.3. Новые таблицы и пункты меню (`cli/modules.php`), версия «было → стало» — на экране и в `logs/update.log`. Пароль admin и данные не меняются.

Откат [не проверено]: `git checkout <прежний коммит>` (или прежний пакет) и `sudo tools/install/linux.sh`, затем восстановление копии из `before-update/` на странице «Сервисные страницы → Резервная копия».

## 3. Если что-то пошло не так

- Сайт отвечает «нет файла config/config.php» — файл настроек удалили или переименовали: верните его из своей копии или заново скопируйте `config/config.example.php` в `config/config.php` и впишите базу.
- Ошибка на странице после обновления — сначала «Сервисные страницы → Обновление программы»: недораспакованный пакет даёт ошибки на отдельных страницах. Подробности ошибки — в `logs/` (файлы `log-<дата>.txt`).
- Данные не те — «Сервисные страницы → Резервная копия» → «Восстановить» из копии, сделанной перед обновлением.

## 4. Что проверено

`tools/install/test-update.sh` — обновление в чистом контейнере Debian 12 со старой версии (сборка 15.10.2026, до переноса кода в модули) на текущую рабочую копию:

```bash
tools/release/build.sh
tools/install/test-update.sh hosting --zip=dist/squirrel-stock-<версия>.zip   # распаковка пакета поверх, кнопка удаления
tools/install/test-update.sh linux                                           # повторный linux.sh
```

Старая версия ставится своим `linux.sh` с демо-базой; к ней добавляются 2FA у admin, облако копий (rclone, папка внутри контейнера), файл в `upload/`, и делается копия старой версией. После обновления проверяется: данные старой версии те же (документы, договоры, единицы оборудования с номерами, остатки, контрагенты, позиции, пользователи, 2FA, настройки), таблицы новой версии созданы, `config/config.php` и `upload/` не изменились, вход с паролем и кодом 2FA, все отчёты меню и сервисные страницы SquirrelStock открываются без ошибок, версия видна в меню и записана в историю и журнал, копия новой версией делается в папку и в облако по старым настройкам; файлов старой версии не остаётся (хостинг — после кнопки на странице «Обновление программы»).

Прогон 16.10.2026, старая версия `f07b0f58a` → текущая: оба режима — «все проверки пройдены». Подробности:

- 4.1. Хостинг: после распаковки поверх осталось 41 файл старой версии (страницы, перенесённые в модули, старые классы копий и оборудования, их шаблоны); программа при этом работала — вход, все отчёты и сервисные страницы открывались. Страница «Обновление программы» показала эти 41 файл, недостающих и изменённых — нет; после кнопки (с подтверждением) — «Файлы сайта совпадают с пакетом», страницы снова открываются. `config/config.php` пакет не затёр. Без `config/config.php` сайт отвечает 503 с подсказкой. [проверено в контейнере; распаковка — `unzip -o`, а не менеджер файлов ISPmanager: как его «Извлечь» поступает с существующими файлами, не проверено — если не заменит, страница покажет «файл отличается»]
- 4.2. Linux: копия старой версией в `before-update/` сделана, 41 файл старой версии удалён самим скриптом, «было → стало» напечатано и записано в `logs/update.log`. Версия в этом прогоне — `dev`: в контейнер копируется рабочая копия без `.git`; из git-копии с историей пишется дата и номер коммита, из пакета — версия пакета [из кода]. Восстановление копии из `before-update/` не проверялось (формат тот же, что у кнопки «Создать копию», её восстановление проверено в `tests/specs/backup.spec.js`).
- 4.3. В обоих режимах: данные старой версии по её столбцам совпали, кроме служебных отметок времени встроенного планировщика Zippy; таблицы новой версии созданы; вход с паролем и кодом 2FA; копия новой версией в папку и в облако с паролем шифрования из старых настроек.
- 4.4. Найдено попутно: демо-база той старой версии была собрана без части таблиц SquirrelStock (2FA, запоминание входа, неудачные входы, интервалы выдачи) — по её инструкции их добавлял файл дополнений форка из db/ (в текущей версии его нет); текущая версия досоздаёт таблицы сама.
