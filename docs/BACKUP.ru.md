# Автоматическая резервная копия

Копия делается сама по расписанию и раскладывается в несколько мест. Настраивается один раз при установке, дальше о ней не нужно помнить: если копии давно не было, программа предупреждает сама.

Пометки: **[проверено]** — на стенде Docker (Linux, PHP 8.2, rclone 1.60) автотестом `tests/specs/backup-auto.spec.js`, **[не проверено]** — по документации; на Windows шаги ещё не проходились.

## Что куда попадает

| Место | Что | Когда |
|---|---|---|
| Папка на этом компьютере | обычный zip (база + прикреплённые файлы) | всегда, по расписанию |
| Папка на другом компьютере или сетевом хранилище | если задан пароль шифрования — тот же зашифрованный zip, что в облако; без пароля — обычный zip | если задана, по расписанию |
| Облака (через rclone), одно или несколько | zip, зашифрованный AES-256 паролем из настроек (один архив на все облака) | если заданы облака и пароль, по расписанию |
| Флешка | обычный zip | вручную: «Сервисные страницы → Резервная копия → Копия на флешку» |

- В каждом месте хранятся последние N копий (по умолчанию 30), старые удаляются. Удаляются только файлы вида `squirrelstock-ГГГГ-ММ-ДД-ЧЧММСС.zip`, чужие файлы в папке не трогаются. [проверено]
- Сбой одного места (сеть недоступна, облако не отвечает) не мешает остальным; ошибка видна на странице, администраторам приходит уведомление (колокольчик). [проверено]
- Без пароля шифрования копия в облако не отправляется: в базе персональные данные. [проверено]
- Сетевая папка лежит на другом компьютере, поэтому при заданном пароле копия туда тоже шифруется. Папка на этом компьютере и флешка получают обычный zip: папка лежит рядом с самой базой, а флешку уносят вручную. Восстановление копии из сетевой папки без пароля не проходит, с паролем — проходит. [проверено]
- Если удачной копии в каком-то месте нет больше 2 суток, на странице «Резервная копия» крупное предупреждение. [проверено]
- Все попытки записываются в таблицу `sqs_backuplog`.

Папка копий не может быть внутри папки сайта: оттуда файлы доступны из браузера. По умолчанию это папка `squirrelstock-backup` рядом с папкой сайта.

## 1. Настройки

«Сервисные страницы → Резервная копия → Автоматическая копия»: папки, облако, пароль, сколько копий хранить. Кнопка «Сохранить и сделать копию сейчас» сразу проверяет все места.

**Пароль шифрования запишите на бумаге и храните отдельно от компьютера.** Без него копию из облака и из сетевой папки не восстановить: программа хранит пароль у себя в базе, а база при поломке компьютера пропадёт вместе с ним.

## 2. Расписание

Скрипт `cli/backup.php` запускает системный планировщик. Удобнее всего запускать его каждый час с `--if-older=20`: если копия моложе 20 часов, скрипт сразу выходит. Тогда копия делается раз в сутки, даже если в какой-то час компьютер был выключен. Точная команда для этой системы показана на странице «Резервная копия».

```
php cli/backup.php                     все места из настроек
php cli/backup.php D:\Backup           папка этого компьютера — эта, а не из настроек
php cli/backup.php --keep=N            хранить N копий в каждом месте
php cli/backup.php --only=local,cloud  только эти места
php cli/backup.php --if-older=20       пропуск, если копия моложе 20 часов
```

Код возврата 0 — все места успешно, 1 — где-то ошибка.

### Windows [не проверено]

Командная строка от имени пользователя, под которым работает программа (у него должен быть доступ к сетевой папке):

```
schtasks /Create /TN "SquirrelStock backup" /SC HOURLY /TR "\"C:\php\php.exe\" \"C:\SquirrelStock\www\cli\backup.php\" --if-older=20"
```

Пути к `php.exe` и к программе — свои; страница «Резервная копия» показывает команду с путями этого компьютера (`php.exe` ищется рядом с `php.ini`, который загрузил Apache). Проверить: `schtasks /Run /TN "SquirrelStock backup"`, затем обновить страницу «Резервная копия».

Сетевая папка указывается как `\\server\share\squirrelstock`, а не буквой диска: подключённые буквы планировщику не видны.

Задача без вошедшего пользователя (от SYSTEM), отдельный пользователь для сетевой папки и файл настроек rclone — [INSTALL_WINDOWS.ru.md](INSTALL_WINDOWS.ru.md), раздел 7.

### Linux: cron [проверено как команда; запуск из cron не проверялся]

`crontab -e` от пользователя веб-сервера (`sudo crontab -u www-data -e`):

```
17 * * * * php /var/www/squirrelstock/cli/backup.php --if-older=20
```

Сетевое хранилище монтируется заранее (`/etc/fstab`, например `//nas/backup /mnt/nas cifs credentials=/root/.nas,uid=www-data 0 0`), в настройках указывается `/mnt/nas/squirrelstock`.

### Linux: systemd timer [не проверено]

`/etc/systemd/system/squirrelstock-backup.service`:

```
[Unit]
Description=SquirrelStock backup

[Service]
Type=oneshot
User=www-data
ExecStart=/usr/bin/php /var/www/squirrelstock/cli/backup.php --if-older=20
```

`/etc/systemd/system/squirrelstock-backup.timer`:

```
[Unit]
Description=SquirrelStock backup hourly

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

`systemctl enable --now squirrelstock-backup.timer`

### Docker [проверено как команда]

Папка копий по умолчанию — том `backups` (`/var/www/squirrelstock-backup` в контейнере). В cron хоста:

```
17 * * * * docker exec -u www-data squirrelstock-web-1 php cli/backup.php --if-older=20
```

Сетевая папка и файл настроек rclone подключаются в контейнер томами (`docker-compose.override.yml`).

## 3. Облака через rclone [проверено с двумя remote типов local и alias; настоящие облака не проверялись]

rclone (https://rclone.org) — одна программа для Яндекс Диска, Google Drive, S3, WebDAV и т. п. В Docker-образ он уже входит; на Windows — скачать `rclone.exe` и указать путь к нему в настройках.

1. От имени пользователя планировщика: `rclone config` → `n` (новый remote) → имя, например `yandex` → тип `yandex` → вход через браузер.
2. Проверить: `rclone lsd yandex:`.
3. В настройках программы: облака — по одному в строке, например `yandex:squirrelstock` и `gdrive:squirrelstock` (копия ~50 МБ уйдёт в каждое), пароль шифрования. Если файл настроек rclone лежит не там, где rclone ищет его по умолчанию (другой пользователь, Docker), — путь к нему в поле «Файл настроек rclone».

Программа только вызывает `rclone copyto`, `rclone lsf`, `rclone deletefile` и проверяет код возврата. У каждого облака своя попытка и строка на странице «Резервная копия» (последняя удачная копия, ошибка), своя ротация — последние N копий; сбой одного облака не мешает остальным, предупреждение о давней копии называет облако. [проверено] Старая настройка с одним облаком работает без изменений. `--only=cloud` — все облака из настройки.

## 4. Восстановление

«Сервисные страницы → Резервная копия → Восстановление из копии»: выбрать файл, для копии из облака или из сетевой папки (если задан пароль) ввести пароль. С неверным паролем база не трогается. [проверено]

Проверки до замены данных (база не трогается):

- выбран не тот файл: не zip с `database.sql` и не дамп `.sql` [проверено];
- введён пароль, а копия не зашифрована (целиком или частично): это не зашифрованная копия из облака или сетевой папки, её могли подменить [проверено];
- после распаковки копия занимает больше свободного места на диске или в ней больше 50 000 файлов [по коду, не проверялось].

Из папки `upload/` копии восстанавливаются только изображения и документы (jpg, png, gif, webp, pdf, txt, csv, офисные файлы, zip). Скрипты, `.htaccess`, скрытые файлы и имена вида `x.php.png` пропускаются, их число показывается в сообщении [проверено]. Файлы, которых нет в копии, остаются в `upload/`.

Размер файла, который можно загрузить через браузер, ограничен настройками PHP: `upload_max_filesize` и `post_max_size`. В Docker и в установке Linux это 64M.

Зашифрованный архив открывается и 7-Zip или WinRAR с тем же паролем; внутри `database.sql` (загружается консольным `mysql`) и папка `upload/`.
