# SquirrelStock: настройка и работа

Руководство для организации, которая бесплатно выдаёт расходные материалы и оборудование получателям (подопечным, семьям, учреждениям). Всё ниже проверено на Docker-стенде из этого репозитория. Установка на Windows описана в [INSTALL_WINDOWS.ru.md](INSTALL_WINDOWS.ru.md), целиком на Windows ещё не проходилась.

## Установка (Docker)

```bash
git clone https://github.com/likemusic/squirrel-stock.git && cd squirrel-stock/docker
SQS_LANG=ru docker compose up -d --build      # http://127.0.0.1:8083, вход admin / admin
```

При первом запуске база создаётся из `db/db.sql` (база Zippy) и `www/app/sqs/schema.sql` (таблицы SquirrelStock). Таблицы и пункты меню SquirrelStock программа создаёт сама: при первом запросе, после обновления программы и после восстановления резервной копии, сделанной более старой версией.

Сразу после входа смените пароль администратора в профиле.

Без Docker: на Debian 12 / Ubuntu 24.04 одним скриптом — [INSTALL_LINUX.ru.md](INSTALL_LINUX.ru.md); на хостинг с Apache — [INSTALL_HOSTING.ru.md](INSTALL_HOSTING.ru.md); обновление программы — [UPDATE.ru.md](UPDATE.ru.md). Какой документ кому — [README.md](README.md).

## Начальная настройка

1. **Профиль для благотворительной организации** — оставляет в меню нужное для выдачи (около 30 пунктов из 90) и выставляет настройки: учёт по серийным номерам, запрет минусовых остатков, цена выдачи 0. На главной не показываются денежные плитки (наличные, безнал, долги) и графики доходов; журнал «Продажи» называется «Выдачи» и открывается со статусом «Все» (проведённые выдачи видны сразу, возврат делается отсюда), в нём нет кнопок доставки, ТТН и гарантийного талона; группы документов «Продажи» и «Закупки» называются «Выдача» и «Поступление», «Расходная накладная» — «Выдача (накладная)», «Возврат от покупателя» — «Возврат от получателя», группа отчётов и отчёт «Закупки» — «Поступление», на странице отчёта — «Отчёт по поступлению» и разделы «Поступление по товарам», «… по поставщикам» и т. д. (название, изменённое вручную в «Настройке меню», профиль не трогает); в формах выдачи и возврата поле «Получатель», нет кассы, цен, скидки и оплаты (цена выдачи всегда 0, оплата не записывается); накладная печатается формой «Выдача № …», «Выдал / Получатель», возврат — «Вернул / Принял», обе без цен и оплаты. Строка «Выдал» — название организации из «Система → Данные компании». Возврат по выдаче, сделанной до включения профиля с ценами, сохраняет цены этой выдачи, оплата по нему не записывается, и он остаётся в статусе «Ожидает оплаты».

   ```bash
   docker exec -u www-data squirrelstock-web-1 php cli/charity-profile.php
   ```

   Вернуть выключенные пункты меню, главную, журнал и печатную форму как в Zippy: тот же скрипт с `--back` (пункты меню — и в «Система → Настройки → Настройка меню»).

2. **Русские названия в базе.** Тексты интерфейса переводятся словарём, а названия документов, пунктов меню, основного склада и кассы лежат в базе на украинском. Перевести их один раз:

   ```bash
   docker exec -u www-data squirrelstock-web-1 php cli/localize-db.php ru
   ```

   После обоих скриптов войдите в программу заново: настройки кэшируются в сессии.

3. **Язык** выбирается в профиле пользователя («Язык интерфейса»), по умолчанию — из `config.php` (в Docker — переменная `SQS_LANG`).

4. **Сумма прописью** в печатных формах: «Система → Настройки → Общие», поле «Валюта суммы прописью» — рубль, гривна, доллар или евро.

5. **Склады для состояний оборудования:** «Справочники → Склады» — добавьте склады «Ремонт» и «К списанию». Единица, перемещённая на такой склад документом «Перемещение ТМЦ», показывается в отчёте об оборудовании с этим состоянием.

6. **Категории товаров**, например «Расходные материалы», «Оборудование» и отдельная группа, по которой нужен отдельный учёт (у хосписа — гастростомы). По категориям отбираются отчёты и составляются отдельные акты.

## Номенклатура и остатки из 1С

«Сервисные страницы → Импорт ведомости 1С» читает оборотно-сальдовую ведомость 1С (.xls, .xlsx):

- по счёту 10 (материалы) — позиции и остатки: позиция ищется по точному названию или создаётся, остаток приходуется по цене «сумма / количество»;
- по счёту 01 (основные средства) — единицы оборудования: товар создаётся с учётом по серийным номерам, каждая единица приходуется со своим инвентарным номером.

Названия остаются как в 1С, чтобы бухгалтерия могла сопоставить акты. Документ прихода создаётся на дату из поля «Дата оприходования»; если поле пустое — на дату ведомости (конец её периода). Повторный импорт не дублирует единицы с инвентарными номерами, а материалы приходует ещё раз.

При первом переносе вместе с историей выдачи оборудования ведомость по счёту 01 приходуйте датой раньше первой выдачи в таблицах (например, 31.12.2017): иначе единица, выданная до даты ведомости, в отчётах на прошлые даты числится выданной раньше, чем появилась на складе. Такая дата обычно раньше начала актуального периода из настроек — администратор отмечает «На время записи снять ограничение закрытого периода»: начало периода сдвигается только на время импорта и возвращается после него (что стояло и что вернули — в сообщении и в журнале программы).

Позиция, пришедшая из ведомости, помнит название из 1С. Акт списания печатает именно его, поэтому позицию можно переименовать в программе — акт не изменится (при переименовании программа об этом напомнит). В 1С бывают две позиции с одним названием и разными ценами: в программе это две позиции, в акте — одна строка. При повторном импорте строки с одинаковым названием сопоставляются позициям по цене с прошлого импорта. Если однозначно сопоставить нельзя (например, одна из одноимённых закончилась, а цена другой изменилась), строки не приходуются и показываются после импорта списком — оприходуйте их вручную на нужную позицию.

## Получатели

Получатель — контрагент в «Справочники → Контрагенты». Признаки получателя — три: «подопечный», «по запросу» (семьи и учреждения вроде пансионата, которым выдают по запросу) и «снят с опеки». В профиле благотворительной организации признак выбирается списком «Признак получателя» в форме контрагента и виден рядом с именем в списке; хранится он тегом контрагента, поэтому по нему работает отбор в списке контрагентов («Признаки и теги» над списком) и в отчёте «Получатели по месяцам». В профиле форма контрагента без торговых полей (холдинг, тип цены, ЕГРПОУ, юр. лицо, адрес доставки, подписки, Viber, Telegram) и без режима лидов; тип «Покупатель» называется «Получатель», новый контрагент — сразу получатель. Справочник проверен на 5 000 контрагентах: список открывается за секунду, подсказка в документе — за доли секунды.

## Расходные материалы

- Поступление — «Приходная накладная» (от донора или поставщика) или «Оприходование ТМЦ».
- Выдача получателю — «Сервисные страницы → Выдача расходников»: получатель (из справочника или новый), дата, позиции с количеством — в подсказке только то, что есть на складе, с остатком; «Выдать» создаёт проведённую расходную накладную по цене 0. Форма короткая и удобна с телефона. Полная «Выдача (накладная)» («Расходная накладная» без профиля) тоже работает.
- Возврат от получателя — «Возврат от получателя» («Возврат от покупателя» без профиля), создаётся на основании выдачи.
- Интервал выдачи — «Справочники → Товары → Интервалы выдачи»: «не чаще раза в N дней» для категории (вместе с подкатегориями) или позиции, например гастростомические трубки раз в 90 дней. Если получатель уже получал такую позицию раньше срока, «Выдача расходников» показывает под строкой красное предупреждение с датой последней выдачи, штатная «Выдача (накладная)» — всплывающее предупреждение после проведения. Выдать всё равно можно (трубка повредилась).
- Списание (порча, истёк срок, брак) — «Списание ТМЦ», причина пишется в примечании.

Повторное нажатие «Провести» на проведённом документе и кнопка «Назад» в браузере после проведения больше не удваивают остатки: программа отказывается проводить документ второй раз. Чтобы изменить проведённый документ, сначала отмените проведение в журнале.

## Оборудование

Каждая единица — товар с учётом по серийным номерам, номер — инвентарный. Заводской номер хранится отдельно: «Справочники → Единицы оборудования» — список единиц с инвентарным и заводским номером и тем, где единица сейчас; заводской номер задаётся здесь. Мелкое оборудование без номера ведите обычным товаром (без флажка серийного учёта), количеством.

Обычная выдача — одной формой «Сервисные страницы → Выдача оборудования по договору»: получатель (из справочника или новый, с телефоном и адресом), договор (номер предлагается следующий, срок или «до востребования», кем направлен) и единицы — в подсказке только те, что есть на складе. «Оформить выдачу» создаёт договор в состоянии «В работе» и проведённую накладную по нему. По шагам — [USER_GUIDE.ru.md](USER_GUIDE.ru.md), раздел 2.

То же штатными документами:

1. **Договор:** «Справочники → Договоры» → «Добавить»: номер (например «234/26»), дата, получатель, дата окончания (срок пользования; «до востребования» — дата 31.12.2099), в «Кратком описании» — кем направлен. Затем откройте договор и переведите его в состояние «В работе» — только такие договоры выбираются в документах.
2. **Выдача:** «Выдача (накладная)» на получателя, в поле «Договор» — этот договор, в строке — инвентарный номер единицы.
3. **Возврат:** «Журналы → Выдачи», в «Контрагент» — получатель, «ОК»; щёлкнуть номер выдачи — кнопка «Возврат» создаёт «Возврат от получателя» на основании выдачи, строки уже заполнены.
4. **Ремонт и списание:** «Перемещение ТМЦ» единицы на склад «Ремонт» или «К списанию»; окончательное списание — «Списание ТМЦ».

Единицу нельзя выдать, переместить, вернуть поставщику или списать (в том числе недостачей по инвентаризации) датой, на которую её нет на складе: например, выдать задним числом раньше возврата по прошлой выдаче. Документ не проводится, сообщение называет номер и дату.

Два взгляда на одни и те же данные:

- «Отчёты → Склад → Оборудование: где сейчас» — каждая единица: на каком складе или у какого получателя, с телефоном, адресом, договором и сроком; просроченный срок выделен красным; поиск по модели, инвентарному или заводскому номеру, получателю; заводской номер — отдельной колонкой, в том числе в Excel; над списком — итог по моделям: сколько выдано, на каждом складе («Ремонт», «К списанию»), списано, всего; под списком — «Мелкое оборудование на руках»: позиции без инвентарных номеров, выданные количеством по договору, — у кого, сколько на руках (выдано минус возвращено), последняя выдача, договор и срок;
- «Отчёты → Склад → Журнал выдачи оборудования» — все выдачи за период с датами возврата; заводской номер — колонкой, поиск по модели, инвентарному или заводскому номеру.

На главной — напоминание: выданное оборудование, у которого срок договора истёк или истекает в ближайшие две недели; мелкое оборудование, выданное количеством по договору, — тоже, строкой с количеством на руках. Срок пользования продлевается кнопкой «Продлить» в напоминании на главной и значком в колонке «Срок» отчёта «Где сейчас»: меняется только дата окончания договора, статус «В работе» остаётся, в комментариях договора записывается, кто и когда изменил срок (было → стало). Штатно договор «В работе» не редактируется.

### Перенос истории выдач из таблиц

«Сервисные страницы → Импорт истории выдачи оборудования» переносит историю из Google-таблиц «Перепись оборудования» и «Журнал выдачи оборудования» (скачать каждую как .xlsx: «Файл → Скачать → Microsoft Excel»).

Порядок:

1. Сначала загрузите единицы из 1С: «Сервисные страницы → Импорт ведомости 1С», ведомость по счёту 01 на дату переноса, «Дата оприходования» — раньше первой выдачи в таблицах (см. выше). Единица с инвентарным номером, которой нет в базе, не импортируется — она попадёт в отчёт со списком недостающих номеров.
2. Потом историю: выберите оба файла и нажмите «Проверить». Ничего не записывается; показывается, что будет создано (получатели, договоры, выдачи, возвраты, списания), ошибки — строки, которые не импортируются (текст вместо даты, несколько единиц в ячейке, «вернули» без даты и т. п.), и заметки — что импортировано с допущением. Исправьте что можно в таблицах и проверьте снова.
3. «Записать». Запись идёт частями: страница показывает, сколько событий записано, и продолжает сама — не закрывайте её (на полной истории хосписа — несколько минут). Если запись оборвалась (закрыли страницу, пропала связь), нажмите «Проверить» и «Записать» снова: записанное не повторится. История старше начала актуального периода из настроек (по умолчанию 1 января текущего года), а документы раньше этой даты программа не сохраняет. Отметьте «На время записи снять ограничение закрытого периода»: начало периода временно переносится на дату самой ранней записи и возвращается после записи, даже если она прервалась; что стояло и что вернули — в результате импорта и в журнале программы. Без отметки запись откажет с объяснением.

Мелочь без номеров, которая ещё на руках, переносится количеством на позицию. Позицию задают «Соответствия наименований» на той же странице: строка «написание в таблице = позиция», например «Ингалят. детский = Ингалятор детский». Так разные написания одного вида сводятся к одной позиции, а сами таблицы править не нужно. Написание, которого в соответствиях нет, не импортируется, а попадает в отчёт («Нет в соответствиях наименований»). Кнопка «Добавить в соответствия» дописывает такие написания в поле, остаётся поправить позицию справа и проверить снова. Соответствия сохраняются при проверке. Написание берётся из колонки «наименование» строки; если она пустая — по названию листа переписи.

Кровати, концентраторы и другое оборудование с инвентарными номерами мелочью не заводятся, даже если номер в строке не вписан. Такую позицию отметьте в соответствиях звёздочкой в конце: «кровати = Кровать медицинская *». Так же считается позиция, название которой совпадает с товаром с учётом по серийным номерам. Строки таких позиций без номера не импортируются, а попадают в отчёт списком «Оборудование без инвентарного номера»: лист и строка, договор, дата выдачи, получатель. Впишите номер в таблицу и проверьте снова.

Одна выдача, записанная в обеих таблицах, импортируется один раз. Повторный импорт тех же файлов не дублирует уже перенесённое, а добавляет новое (например, вписанную потом дату возврата).

Проверка ловит то, что при записи не пройдёт: единицу, выданную повторно раньше даты возврата по прошлой выдаче (по таблицам она в это время у другого получателя), и договор, который уже записан на другое ФИО (в программе или в более ранней строке таблиц). Такие строки — ошибки: исправьте даты или ФИО в таблице и проверьте снова. Дата возврата в будущем считается плановым сроком: единица остаётся у получателя, дата становится сроком договора, если срок не указан (заметка в отчёте). Если событие всё же не записалось, в отчёте — причина и что из-за него пропущено (например, возврат той же строки); остальные строки записываются.

## Отчёты

- **Акт списания за месяц** — в формате бухгалтерии: строки — позиции, колонки — выдачи «Получатель дд.мм.гггг», итоги; возвраты вычитаются. Отдельные акты на расходники и на оборудование: поле «Что списано» — «Расходники» (по умолчанию), «Оборудование (по договорам)» (единицы с инвентарным номером и всё, что выдано по договору, в том числе мелочь количеством) или «Всё вместе»; заголовок по умолчанию меняется вместе с выбором. Отбор по категории, выгрузка в Excel.
- **Списания с причинами** — документы «Списание ТМЦ» за период: дата, документ, склад, позиция, инвентарный номер, количество и причина (примечание документа). Отбор по категории и по тексту причины, печать и Excel.
- **Получатели по месяцам** — кто в каком месяце получал: отметка «х», количество или число выдач; отбор по категории, позиции и тегу получателя.
- **Карточка получателя** — всё по одному подопечному на одной странице: контакты и «кем направлен» (краткое описание договоров), оборудование на руках (единицы и мелкое, договор, срок, кнопка «Продлить»), выданные расходники за период по позициям и по месяцам (за вычетом возвратов; выданное по договору считается оборудованием), выдачи и возвраты со ссылкой на документ, когда можно следующую выдачу по интервалам выдачи. Открывается по ссылке у имени в журнале выдач, значком в справочнике контрагентов или поиском по ФИО и телефону на самой странице; печать и Excel.
- **Оборот по позициям** — на начало, приход, выдано, возвращено, списано, прочее, на конец, число выдач; с отбором по получателю — что ему выдано за период.
- **Ниже минимального остатка** — список для закупки: позиции, у которых остаток меньше «Мин. количества» из карточки позиции (справочник номенклатуры), сколько не хватает до минимума, последнее поступление и от кого. В списке и позиции, которых на складе ещё не было. Отбор по складу и категории, выгрузка в Excel.
- Штатные отчёты Zippy: «Состояние складов», «Движение по складу», «Закупки» (в профиле — «Поступление»).

## Резервная копия

«Сервисные страницы → Резервная копия» → «Создать копию» скачивает zip с базой и прикреплёнными файлами. Делайте копию каждый день в конце работы и храните не на этом компьютере. Восстановление — там же, с подтверждением: текущие данные заменяются данными из копии. Файл `database.sql` из архива загружается и обычным клиентом `mysql`.

Автоматическая копия по расписанию — в папку на этом компьютере, в сетевую папку и в одно или несколько облаков (зашифрованной), с предупреждением, если копии давно не было: настройка и расписание — [BACKUP.ru.md](BACKUP.ru.md).

## Без интернета

Программа не обращается к внешним адресам: графики рисуются локальной библиотекой, проверка обновлений Zippy с сайта автора отключена. Проверено на стенде без выхода в сеть (`docker/docker-compose.offline.yml`).

## Вход и защита

- После пяти неудачных попыток входа по одному логину (или двадцати с одного адреса) за 15 минут вход на время закрывается; счётчик хранится в базе, новая сессия его не сбрасывает.
- «Запомнить меня» — случайный токен на 14 дней; он перестаёт действовать при смене пароля и при выходе.
- Двухфакторный вход: каждый пользователь включает его сам в «Мой профиль → Двухфакторный вход» (приложение-аутентификатор, резервные коды), администратор сбрасывает его пользователю, потерявшему телефон. По шагам — [USER_GUIDE.ru.md](USER_GUIDE.ru.md), раздел 10.
- Журнал правок документов: при просмотре документа из журнала видно, кто и когда что изменил (было → стало): номер, дату, получателя, склад, примечание, сумму, строки. Строки, дату, склад и получателя проведённого документа нельзя изменить без отмены проведения.
- Сайт, открытый в интернет, проверяется скриптом `tools/release/check-site.sh` (HTTPS, заголовки, закрытые служебные адреса, cookie) — [INSTALL_HOSTING.ru.md](INSTALL_HOSTING.ru.md), раздел 9.
