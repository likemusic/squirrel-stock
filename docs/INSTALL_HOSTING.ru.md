# Установка SquirrelStock на хостинг (ISPmanager, Apache)

Для демонстрации или работы через интернет. Пометки: **[проверено]** — сделано на копии «как на хостинге»: Apache с PHP в Docker без своих настроек PHP и Apache, кроме шага 2.3, отдельная MariaDB с включённым бинарным журналом, обычный пользователь базы без root-прав. Копии: 16.10.2026 — PHP 8.2, MariaDB 10.11, импорт через phpMyAdmin 5.2; 18.10.2026 — PHP 8.4, MariaDB 11.4, импорт консольным `mariadb`, каждый шаг по этой инструкции. **[не проверено]** — по документации и опыту; в настоящей панели ISPmanager шаги ещё не проходились, названия пунктов даны по ISPmanager 6.

## 0. Перед началом

- **На демо-сервер — только вымышленные данные.** Программа открыта в интернет, вход защищает только пароль.
- **Только корень сайта.** В `.htaccess` стоит `RewriteBase /`, поэтому нужен отдельный поддомен (`stock.example.org`), подпапка `example.org/stock/` не подойдёт.
- **Нужен Apache** («PHP как модуль Apache», «CGI» или «FastCGI (Apache)»). В режиме «Nginx + PHP-FPM» `.htaccess` не читается, и файл с паролем базы становится доступен из браузера (см. раздел 8).

## 1. Что подготовить

Собрать пакет на машине с Docker: `tools/release/build.sh`. В конце сборка печатает пароль `admin` для обеих баз пакета — **запишите его**: он нигде не сохраняется. В папке `dist/` появятся:

| Файл | Что это |
|---|---|
| `squirrel-stock-<версия>.zip` (~26 МБ) | содержимое корня сайта: код, зависимости composer (`vendor/`), `config/config.example.php` для заполнения, версия и список файлов пакета (`config/version.txt`, `config/manifest.txt`) |
| `squirrel-stock-<версия>-demo.sql` | демо-база с вымышленными данными: 44 позиции, 20 получателей, 73 документа, 8 договоров на оборудование (у трёх срок истекает — напоминание на главной); меню и настройки для благотворительной организации, русские названия. Вход `admin` с паролем, который `build.sh` напечатал при сборке |
| `squirrel-stock-<версия>-empty.sql` | пустая база (Zippy + страницы SquirrelStock). Вход `admin` с тем же паролем из сборки |
| `squirrel-stock-<версия>.sha256` | контрольные суммы |

Требования: PHP 8.2–8.4 (полный набор автотестов пройден на 8.2 с MariaDB 10.11 и на 8.4 с MariaDB 11.4; лучше 8.4: поддержка 8.2 у разработчиков PHP заканчивается 31.12.2026, 8.4 — 31.12.2028; 8.1 не проверялась), MySQL 5.7+ или MariaDB (проверено на 10.11 и 11.4), расширения mysqli, zip, gmp, gd, mbstring, curl, fileinfo, openssl, xml, dom, iconv, json. Чаще всего на хостинге не включены **gmp**, иногда **zip** и **gd**.

## 2. Поддомен и сайт [не проверено]

1. A-запись поддомена: если DNS обслуживает этот же сервер, ISPmanager создаст её сам; иначе добавьте A-запись у регистратора или в Cloudflare с IP сервера.
2. ISPmanager → **Сайты** → **Создать сайт**: имя `stock.example.org`; обработчик — «PHP как модуль Apache» или «FastCGI (Apache)»; версия PHP 8.4 (если её нет в списке — 8.3 или 8.2); **SSL** — Let's Encrypt и «Перенаправлять HTTP-запросы в HTTPS».
3. Настройки PHP сайта: `memory_limit = 512M`, `max_execution_time = 300`, `date.timezone = Europe/Minsk`, `upload_max_filesize` и `post_max_size` — не меньше 64M (импорт Excel, восстановление из копии). Если пределы не заданы, долгие операции (проверка и запись импорта истории оборудования, импорт 1С и Excel, создание копии и восстановление) поднимают время до 300 с и память до 512M сами; если хостинг этого не даёт (`set_time_limit` в `disable_functions`, значения закреплены администратором), операция на больших данных обрывается, и вместо неё страница с просьбой поставить эти значения, а в журнале программы — строка `SquirrelStock limits`. [проверено на стенде Docker: заниженные пределы через `php_value` и `php_admin_value`]

## 3. База данных

Пользователю базы нужны **все права на эту базу** — `ALL PRIVILEGES` (в ISPmanager пользователь, созданный вместе с базой, обычно их и получает [не проверено]). Таблицы SquirrelStock (вход, оборудование, расходники, резервная копия) программа создаёт и досоздаёт сама: при первом запросе, после обновления и после восстановления старой копии; при обновлении она же меняет столбцы ([MODULES.md](MODULES.md)). [проверено на стенде Docker]

Если права пользователю выдают по списку, нужны: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `CREATE`, `DROP`, `ALTER`, `INDEX`, `CREATE VIEW`, `SHOW VIEW`, `TRIGGER`. Что бывает без них [проверено на MariaDB 11.4, 18.10.2026]:

- 3.1. Без `CREATE` или `DROP` не открываются страницы, которым нужна служебная таблица (главная, отчёт «Движение по ТМЦ»): вместо них — «Пользователю базы данных не хватает права CREATE…». Таблицы новых модулей не создаются.
- 3.2. Без `ALTER` цена партии остаётся с 2 знаками, и настройка «Цена партии: точная» не включается — страница настроек говорит почему.
- 3.3. Структура базы, которую программа не смогла обновить, видна администратору: на главной и на странице «Сервисные страницы → Обновление программы» — какой файл и что ответила база. Попытка повторяется при следующем входе; `php cli/modules.php` в этом случае печатает ошибку и завершается с кодом 1.
- 3.4. Без `SHOW VIEW` резервная копия не создаётся (сообщение называет право). Без `CREATE`, `ALTER`, `CREATE VIEW`, `TRIGGER` или `DROP` восстановление из копии отказывает до удаления таблиц: данные не трогаются (без `CREATE`, `CREATE VIEW`, `TRIGGER` — проверено, без `ALTER` и `DROP` — по коду: проверка та же).

1. ISPmanager → **Базы данных** → **Создать**: MySQL/MariaDB, имя и пользователь (панель может добавить префикс: `u123_stock`), длинный пароль, кодировка utf8. [не проверено]
2. phpMyAdmin → эта база → **Импорт** → `squirrel-stock-<версия>-demo.sql` (или `-empty.sql`) → кнопка «Импорт» внизу страницы (в старых версиях — «Вперёд»). Ожидаемый ответ: «Импорт успешно завершён, выполнено … запросов» (в английском интерфейсе «Import has been successfully finished, … queries executed»; число запросов зависит от версии пакета). [проверено 18.10.2026 в phpMyAdmin 5.2.3 на MariaDB 11.4: оба файла пакета] Если есть доступ по SSH, то же из консоли: `mariadb -u u123_stock -p u123_stock < squirrel-stock-<версия>-demo.sql` — без сообщений, если всё прошло. [проверено]
3. Проверить, что создались триггеры (их создаёт конец файла, поэтому оборванный импорт виден именно здесь): вкладка «Триггеры» (в phpMyAdmin 5.2 — в меню «Ещё») → `entrylist_after_ins_tr` и `entrylist_after_del_tr`. Без них не ведутся остатки. [проверено]
4. **Ошибка `#1419 You do not have the SUPER privilege and binary logging is enabled`** бывает на серверах с включённым бинарным журналом. phpMyAdmin показывает красный блок «Ошибка» с запросом `DROP TRIGGER IF EXISTS …` (для `-demo.sql`) или `CREATE TRIGGER …` (для `-empty.sql`; над ним ещё «Статический анализ: Найдено 2 ошибок» — это замечания самого phpMyAdmin, не важно) и «Ответ MySQL: #1419». Импорт остановлен на триггерах: таблицы и данные уже созданы, триггеров нет — остатки вестись не будут, сайт до успешного импорта не открывать. Попросите администратора сервера включить `log_bin_trust_function_creators=1` (или сделайте это сами, если сервер ваш: в ISPmanager — «Серверы баз данных» → параметры) и повторите импорт. `-demo.sql` импортируйте повторно поверх: он сам удаляет свои таблицы. Перед повторным импортом `-empty.sql` удалите все таблицы базы: вкладка «Структура» → «Отметить все» → «С отмеченными:» → «Удалить» → **снимите** «Включить проверку внешних ключей» → «Да» (с этой отметкой часть таблиц остаётся); иначе — ошибка `Table ... already exists`. Пароль `admin` из сборки записывается в базу раньше триггеров, так что и оборванный импорт не оставляет известного пароля. [проверено 18.10.2026: phpMyAdmin 5.2.3 и консольный `mariadb`, MariaDB 11.4 с бинарным журналом, обычный пользователь базы — ошибка на обоих файлах, пароль из сборки на месте, повторный импорт после включения параметра — для `-demo.sql` поверх, для `-empty.sql` после удаления таблиц]

## 4. Файлы

1. ISPmanager → **Менеджер файлов** → корень сайта; удалить заглушку панели (`index.html`).
2. Закачать `squirrel-stock-<версия>.zip` → **Извлечь** в текущую папку. В корне должны оказаться `index.php`, `.htaccess`, папки `app`, `config`, `vendor`, `upload`, `logs`. Если файлы оказались во вложенной папке — перенести на уровень выше. Zip удалить.
3. Скопировать `config/config.example.php` в `config/config.php` (в менеджере файлов — «Копировать») и вписать базу. Своего `config.php` в пакете нет, чтобы распаковка нового пакета при обновлении не затирала настройки; пока файла нет, сайт отвечает «нет файла config/config.php» (код 503). [проверено]
   ```php
   $_config['db']['host'] = 'localhost';
   $_config['db']['name'] = 'u123_stock';
   $_config['db']['user'] = 'u123_stock';
   $_config['db']['pass'] = 'ПАРОЛЬ_БАЗЫ';
   ```
   Язык по умолчанию — `ru` (`$_config['common']['lang']`), у каждого пользователя меняется в профиле.
4. Папки `upload` и `logs` должны быть доступны PHP на запись. Обычно сайт работает от владельца файлов, и хватает 755; если нет — 775.
5. Временная папка. В ISPmanager PHP сайта обычно ограничен `open_basedir` папкой пользователя, и системная `/tmp` ему недоступна. Резервная копия и импорт истории оборудования тогда берут `upload_tmp_dir` из настроек PHP сайта, а если он не задан — создают папку `tmp/` в корне сайта; она закрыта от браузера. Если копия или импорт пишут «Нет временной папки…», задайте `upload_tmp_dir` (ISPmanager → сайт → «Настройки PHP») внутри папки пользователя, например `/var/www/<пользователь>/data/tmp`, или дайте PHP права на запись в корень сайта; путь, который не подошёл, записан в журнале `logs/`. [проверено на стенде Docker: `open_basedir` без `/tmp` — с `upload_tmp_dir` и без него; в настоящей панели не проверено]

## 5. Проверка и первый вход

1. Из браузера должны отдавать 403: `/config/config.php`, `/app/system.php`, `/templates/pages/base.html`, `/logs/`, `/upload/`, `/composer.json`, `/lang/ru.json`, `/vendor/autoload.php`. [проверено на копии с Apache]
   В папке `upload/` браузеру отдаются только картинки (jpg, png, gif, webp), остальные файлы — 403, и PHP там не выполняется. Это задают правило в корневом `.htaccess` и `upload/.htaccess` [проверено в Docker с Apache и mod_php; на хостинге с другим обработчиком PHP не проверялось]. Если хостинг запрещает в `.htaccess` директивы `RemoveHandler` и `php_flag`, `upload/` целиком отвечает 500: файлы остаются закрытыми, но не открываются и картинки.
2. Войти `admin` с паролем из сборки. Если его не сохранили — заново собрать пакет и импортировать базу.
3. С демо-базой больше ничего настраивать не нужно. С пустой базой — [GUIDE.ru.md](GUIDE.ru.md), раздел «Начальная настройка»; скрипты `cli/*.php` запускаются по SSH (`php cli/charity-profile.php`), из браузера они не работают.

4. После выкладки и после каждого обновления запустить проверку сайта — раздел 9.

Проверено на копии 18.10.2026 (PHP 8.4, MariaDB 11.4): вход паролем из сборки, весь сценарий показа скриптом — главная с напоминаниями о договорах, карточка получателя и «Продлить», справочник контрагентов с признаками, выдача расходников с предупреждением об интервале, выдача оборудования по договору (поле «Кем направлен» подставляется из прошлого договора), возврат, акты «Расходники» и «Оборудование» в Excel, «Списания с причинами», резервная копия, «Сервисные страницы → Обновление программы» («Файлы сайта совпадают с пакетом этой версии»); ни одного запроса к внешним адресам. Ранее, 16.10.2026: вход, русский интерфейс, все 44 страницы меню демо-базы без ошибок, отчёты «Акт списания», «Получатели по месяцам», «Оборот по позициям», «Оборудование: где сейчас», «Журнал выдачи оборудования», создание резервной копии и восстановление из неё, ни одного запроса к внешним адресам.

## 6. Защита

- Длинный пароль администратора; HTTPS с перенаправлением (шаг 2.2).
- Демо в интернете — только по HTTPS: по обычному HTTP браузер не сообщает, с какого сайта пришёл запрос, и программа проверяет источник действий по менее надёжному заголовку Referer.
- Настройки PHP сайта (ISPmanager → сайт → «Настройки PHP»): `expose_php = Off`, `display_errors = Off`. [не проверено в панели] Флаги cookie сессии (`HttpOnly`, `SameSite=Lax`, `use_strict_mode`, при HTTPS — `Secure`) программа ставит сама, в настройках PHP их задавать не нужно. [HttpOnly и SameSite проверены `check-site.sh` на копии без этих настроек PHP; Secure — по коду, `init.php`]
- Капча на входе: «Система → Настройки → Администратор», отметка «Капча на форме входа». Защищает от автоматического подбора пароля.
- Двухфакторный вход: каждый пользователь включает его сам — «Профиль → Двухфакторный вход» (приложение-аутентификатор на телефоне: Google Authenticator, Aegis, FreeOTP). Резервные коды показываются один раз — записать. Потерянный телефон: администратор сбрасывает вход там же, на странице «Двухфакторный вход». Для пользователя с двухфакторным входом не работает вход только по паролю через API и Telegram-бота.
- API (`/api/...`) и Telegram-бот, если не используются: закрыть API в `.htaccess` строкой `RewriteRule ^api/ - [F,L]` после `RewriteBase`. [не проверено]
- Заголовки безопасности и запрет служебных файлов уже в `.htaccess` (нужен модуль Apache `mod_headers`, обычно включён), в том числе Content-Security-Policy: страницы загружают и отправляют данные только на свой адрес и не встраиваются в чужие сайты. Магазин (модуль, хоспису не нужен) — без этой политики: его платёжные виджеты грузятся с чужих адресов. HSTS (`Strict-Transport-Security`) добавляйте в `.htaccess` только после того, как HTTPS работает: иначе браузеры не откроют сайт по HTTP до конца срока заголовка.
- Второй пароль на весь поддомен: ISPmanager → сайт → «Ограничение доступа» (HTTP-авторизация). [не проверено]
- Не публиковать адрес и не ставить на него ссылки.

## 7. Резервная копия и сброс демо

- «Сервисные страницы → Резервная копия» → «Создать копию» — zip с базой и вложениями; восстановление там же. [проверено на копии]
- Вернуть демо в исходное состояние: «Восстановить» из `db/demo/squirrelstock-demo.zip` или заново импортировать `-demo.sql` в пустую базу. После восстановления из `db/demo` пароль станет `admin` — **сразу смените его** (справа вверху → «Профиль»); `-demo.sql` из пакета восстанавливает пароль из сборки.
- Если phpMyAdmin недоступен (а сайт уже работает), `-demo.sql` пакета можно загрузить той же страницей: «Восстановление из копии» → выбрать файл `.sql` → отметка «Понимаю…» → «Восстановить». Пароль admin после этого — из сборки пакета. Для первой установки страница не подходит: ей нужна уже импортированная база. [проверено на стенде Docker: дамп со строками, которые дописывает сборка, восстанавливается страницей, `tests/specs/restore-sql.spec.js`; пакеты до 23.10.2026 содержали строку, на которой восстановление обрывалось, — их загружать страницей только версией программы с этим исправлением]
- Встроенного обновления с сайта Zippy в SquirrelStock нет (отключено), обновление — новой сборкой пакета: копия, распаковка поверх, удаление файлов старых версий на странице «Сервисные страницы → Обновление программы». Порядок — [UPDATE.ru.md](UPDATE.ru.md).

## 8. Если доступен только «Nginx + PHP-FPM» [не проверено]

Попросить администратора добавить в конфигурацию nginx сайта:

```nginx
location ~ ^/(config|logs|app|templates|upload|cli)/ { deny all; }
location / { try_files $uri /index.php?$args; }
```

После этого проверить пункт 5.1.

## 9. Проверка выложенного сайта: `check-site.sh`

На машине с копией репозитория (нужны bash и curl; Linux, macOS или WSL):

```bash
tools/release/check-site.sh https://stock.example.org
SQS_CHECK_PASS='пароль admin' tools/release/check-site.sh https://stock.example.org   # с проверками после входа
```

Скрипт только читает: делает запросы GET к этому сайту, а если задан пароль, один раз входит и выходит. Ничего не меняет и к другим адресам не обращается. По каждому пункту печатает `OK`, `ОШИБКА`, `ПРЕДУПРЕЖДЕНИЕ` или `пропущено`. Код выхода 1, если есть ошибки.

- 9.1. HTTPS: сертификат действителен, до конца срока больше 14 дней, HTTP перенаправляет на HTTPS (шаг 2.2). Перенаправление на адрес с `:443` (`https://stock.example.org:443/`, так делает ISPmanager) — тот же адрес, это не ошибка.
- 9.2. Заголовки страницы входа: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, нет X-Powered-By. HSTS (`Strict-Transport-Security`): если его нет — предупреждение с готовой строкой для `.htaccess` (раздел 6).
- 9.3. Служебные адреса отвечают 403 или 404: адреса из шага 5.1, `cli/`, `init.php`, `.htaccess`, `db/`, файлы `upload/`, кроме картинок. Если сервер обрывает соединение, ничего не ответив (nginx хостинга так закрывает `.htaccess` и `README.md`), это тоже «закрыт»: скрипт перечисляет такие адреса отдельной строкой. Файлы css и js, нужные страницам, открываются.
- 9.4. Cookie сессии: HttpOnly, SameSite, Secure (раздел 6).
- 9.5. Несуществующие страницы не показывают путей на сервере и текста ошибок PHP (`display_errors = Off`).
- 9.6. Вход (`SQS_CHECK_PASS`, логин — `SQS_CHECK_USER`, по умолчанию `admin`): пароль принят. Если двухфакторный вход не включён — предупреждение. Если включён — скрипт кода не вводит, и проверки после входа пропускаются. С капчей на входе вход не проверяется. Неверный пароль программа считает неудачной попыткой входа.
- 9.7. После входа: обновления Zippy с сайта автора отключены (нет ссылки в меню, страница сообщает «отключено»).

Между запросами скрипт делает паузу 0,2 с (`SQS_CHECK_DELAY`, в секундах). Если у сайта в панели включена защита от DDoS (ограничение числа запросов в секунду), при превышении сервер отвечает 503 или рвёт соединение; такие запросы скрипт повторяет ещё два раза, через 2 и 4 с. Если 503 остаются, увеличьте паузу: `SQS_CHECK_DELAY=1`.
