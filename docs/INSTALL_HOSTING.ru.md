# Установка SquirrelStock на хостинг (ISPmanager, Apache)

Для демонстрации или работы через интернет. Пометки: **[проверено]** — сделано на копии «как на хостинге» (PHP 8.2 + Apache в Docker, отдельная MariaDB 10.11 с включённым бинарным журналом, обычный пользователь базы без root-прав, импорт через phpMyAdmin 5.2), **[не проверено]** — по документации и опыту; в настоящей панели ISPmanager шаги ещё не проходились, названия пунктов даны по ISPmanager 6.

## 0. Перед началом

- **На демо-сервер — только вымышленные данные.** Программа открыта в интернет, вход защищает только пароль.
- **Только корень сайта.** В `.htaccess` стоит `RewriteBase /`, поэтому нужен отдельный поддомен (`stock.example.org`), подпапка `example.org/stock/` не подойдёт.
- **Нужен Apache** («PHP как модуль Apache», «CGI» или «FastCGI (Apache)»). В режиме «Nginx + PHP-FPM» `.htaccess` не читается, и файл с паролем базы становится доступен из браузера (см. раздел 8).

## 1. Что подготовить

Собрать пакет на машине с Docker: `tools/release/build.sh`. В конце сборка печатает пароль `admin` для обеих баз пакета — **запишите его**: он нигде не сохраняется. В папке `dist/` появятся:

| Файл | Что это |
|---|---|
| `squirrel-stock-<версия>.zip` (~25 МБ) | содержимое корня сайта: код, зависимости composer (`vendor/`), `config/config.php` для заполнения |
| `squirrel-stock-<версия>-demo.sql` | демо-база с вымышленными данными: 41 позиция, 20 получателей, 54 документа, 8 договоров на оборудование (у трёх срок истекает — напоминание на главной); меню и настройки для благотворительной организации, русские названия. Вход `admin` с паролем, который `build.sh` напечатал при сборке |
| `squirrel-stock-<версия>-empty.sql` | пустая база (Zippy + страницы SquirrelStock). Вход `admin` с тем же паролем из сборки |
| `squirrel-stock-<версия>.sha256` | контрольные суммы |

Требования: PHP 8.1 или новее (проверено на 8.2), MySQL 5.7+ или MariaDB (проверено на 10.11), расширения mysqli, zip, gmp, gd, mbstring, curl, fileinfo, openssl, xml, dom, iconv, json. Чаще всего на хостинге не включены **gmp**, иногда **zip** и **gd**.

## 2. Поддомен и сайт [не проверено]

1. A-запись поддомена: если DNS обслуживает этот же сервер, ISPmanager создаст её сам; иначе добавьте A-запись у регистратора или в Cloudflare с IP сервера.
2. ISPmanager → **Сайты** → **Создать сайт**: имя `stock.example.org`; обработчик — «PHP как модуль Apache» или «FastCGI (Apache)»; версия PHP 8.2; **SSL** — Let's Encrypt и «Перенаправлять HTTP-запросы в HTTPS».
3. Настройки PHP сайта: `memory_limit = 512M`, `max_execution_time = 300`, `date.timezone = Europe/Minsk`, `upload_max_filesize` и `post_max_size` — не меньше 64M (импорт Excel, восстановление из копии).

## 3. База данных

Пользователю базы нужно право CREATE: таблицы модулей (оборудование, расходники, резервная копия) программа создаёт сама при первом запросе (docs/MODULES.md). [проверено на стенде Docker]

1. ISPmanager → **Базы данных** → **Создать**: MySQL/MariaDB, имя и пользователь (панель может добавить префикс: `u123_stock`), длинный пароль, кодировка utf8. [не проверено]
2. phpMyAdmin → эта база → **Импорт** → `squirrel-stock-<версия>-demo.sql` (или `-empty.sql`) → «Вперёд». Ожидаемый ответ: «Import has been successfully finished, 226 queries executed». [проверено]
3. Проверить, что создались триггеры: вкладка «Триггеры» → `entrylist_after_ins_tr` и `entrylist_after_del_tr`. Без них не ведутся остатки. [проверено]
4. **Ошибка `#1419 You do not have the SUPER privilege and binary logging is enabled`** на `CREATE TRIGGER` бывает на серверах с включённым бинарным журналом. Удалите созданные таблицы, попросите администратора сервера включить `log_bin_trust_function_creators=1` (или сделайте это сами, если сервер ваш: в ISPmanager — «Серверы баз данных» → параметры) и повторите импорт. [проверено с включённым журналом и `log_bin_trust_function_creators=1` — импорт проходит; ошибка без этого параметра проверялась на базе Zippy, на базе SquirrelStock — нет]

## 4. Файлы

1. ISPmanager → **Менеджер файлов** → корень сайта; удалить заглушку панели (`index.html`).
2. Закачать `squirrel-stock-<версия>.zip` → **Извлечь** в текущую папку. В корне должны оказаться `index.php`, `.htaccess`, папки `app`, `config`, `vendor`, `upload`, `logs`. Если файлы оказались во вложенной папке — перенести на уровень выше. Zip удалить.
3. `config/config.php` — вписать базу:
   ```php
   $_config['db']['host'] = 'localhost';
   $_config['db']['name'] = 'u123_stock';
   $_config['db']['user'] = 'u123_stock';
   $_config['db']['pass'] = 'ПАРОЛЬ_БАЗЫ';
   ```
   Язык по умолчанию — `ru` (`$_config['common']['lang']`), у каждого пользователя меняется в профиле.
4. Папки `upload` и `logs` должны быть доступны PHP на запись. Обычно сайт работает от владельца файлов, и хватает 755; если нет — 775.

## 5. Проверка и первый вход

1. Из браузера должны отдавать 403: `/config/config.php`, `/app/system.php`, `/templates/pages/base.html`, `/logs/`, `/upload/`, `/composer.json`, `/lang/ru.json`, `/vendor/autoload.php`. [проверено на копии с Apache]
2. Войти `admin` с паролем из сборки. Если его не сохранили — заново собрать пакет и импортировать базу.
3. С демо-базой больше ничего настраивать не нужно. С пустой базой — `docs/GUIDE.ru.md`, раздел «Начальная настройка»; скрипты `cli/*.php` запускаются по SSH (`php cli/charity-profile.php`), из браузера они не работают.

Проверено на копии: вход, русский интерфейс, все 44 страницы меню демо-базы без ошибок, отчёты «Акт списания», «Получатели по месяцам», «Оборот по позициям», «Оборудование: где сейчас», «Журнал выдачи оборудования», создание резервной копии и восстановление из неё, ни одного запроса к внешним адресам.

## 6. Защита

- Длинный пароль администратора; HTTPS с перенаправлением (шаг 2.2).
- Настройки PHP сайта (ISPmanager → сайт → «Настройки PHP»): `session.cookie_httponly = On`, `session.cookie_secure = On` (только при HTTPS), `session.cookie_samesite = Lax`, `session.use_strict_mode = On`, `expose_php = Off`, `display_errors = Off`. [не проверено]
- Капча на входе: «Настройки → Общие → капча». Защищает от автоматического подбора пароля.
- Двухфакторный вход: каждый пользователь включает его сам — «Профиль → Двухфакторный вход» (приложение-аутентификатор на телефоне: Google Authenticator, Aegis, FreeOTP). Резервные коды показываются один раз — записать. Потерянный телефон: администратор сбрасывает вход там же, на странице «Двухфакторный вход». Для пользователя с двухфакторным входом не работает вход только по паролю через API и Telegram-бота.
- API (`/api/...`) и Telegram-бот, если не используются: закрыть API в `.htaccess` строкой `RewriteRule ^api/ - [F,L]` после `RewriteBase`. [не проверено]
- Заголовки безопасности и запрет служебных файлов уже в `.htaccess` (нужен модуль Apache `mod_headers`, обычно включён). HSTS (`Strict-Transport-Security`) добавляйте в `.htaccess` только после того, как HTTPS работает: иначе браузеры не откроют сайт по HTTP до конца срока заголовка.
- Второй пароль на весь поддомен: ISPmanager → сайт → «Ограничение доступа» (HTTP-авторизация). [не проверено]
- Не публиковать адрес и не ставить на него ссылки.

## 7. Резервная копия и сброс демо

- «Сервис → Резервная копия» → «Создать копию» — zip с базой и вложениями; восстановление там же. [проверено на копии]
- Вернуть демо в исходное состояние: «Восстановить» из `db/demo/squirrelstock-demo.zip` или заново импортировать `-demo.sql` в пустую базу. После восстановления из `db/demo` пароль станет `admin` — **сразу смените его** (справа вверху → «Профиль»); `-demo.sql` из пакета восстанавливает пароль из сборки.
- Встроенного обновления с сайта Zippy в SquirrelStock нет (отключено), обновление — новой сборкой пакета: заменить файлы, кроме `config/config.php`, `upload/`, `logs/`.

## 8. Если доступен только «Nginx + PHP-FPM» [не проверено]

Попросить администратора добавить в конфигурацию nginx сайта:

```nginx
location ~ ^/(config|logs|app|templates|upload|cli)/ { deny all; }
location / { try_files $uri /index.php?$args; }
```

После этого проверить пункт 5.1.
